# 数据目录

这个目录在版本控制中只包含本说明文件。运行生成脚本后，本地会额外出现：

- `demo.sqlite3`：完全由虚构科目、章节、知识点、题目和作答记录组成的合成演示数据库；该文件受 `.gitignore` 保护，不会提交到仓库。

演示数据仅用于展示界面、验证公式和运行测试。它采用看板所需的 v10 兼容结构子集，不是完整复习数据库，不能用于维护回填。它不代表真实考试结构、真实考频、真实成绩或任何个人的学习情况，也不应被用于教学结论或备考决策。

可以随时从仓库根目录重新生成它：

```bash
python3 scripts/create_demo_database.py
```

## 私人数据库应放在哪里

真实数据库必须保存在仓库之外。启动时通过 `--database` 指向仓库外的文件，例如：

```bash
python3 scripts/mistake_dashboard_server.py \
  --database ../private-data/312-review.sqlite3 \
  --port 4174
```

不要把私人文件复制到本目录，不要用真实数据库覆盖 `demo.sqlite3`，也不要用 `git add -f` 绕过 `.gitignore`。SQLite 的 `-wal`、`-shm`、journal、备份和导出文件可能包含已删除或尚未合并的数据，同样不能提交。

## 为什么简单删字段不够

学习数据库可能通过题干组合、作答日期、章节顺序、错误描述、稳定 ID、分数轨迹或稀有知识点间接识别个人。因此：

- 删除姓名或联系方式不等于匿名化；
- 替换题干但保留真实日期与分数也不等于合成数据；
- 从真实记录抽样、打乱或加入噪声仍可能泄露原始行为；
- 最安全的公开样例是从零生成彼此无关的虚构记录。

对演示数据生成逻辑的任何更新都必须保持全合成，并通过测试和严格数据校验；生成产物仍不得提交。
